## Four Beats

1. **Name the case.** Give the PowerWorld Simulator session a short title before you edit buses or branches.
2. **Pin the live view.** Keep current buses, branches, and limits on the PowerWorld Simulator board and leave unused areas aside.
3. **Check the list.** Read the PowerWorld Simulator summary of the contingency list before you open another outage.
4. **Close the loop.** Note which outage is next so the following PowerWorld Simulator visit does not start by searching the oneline diagram.

## Field Note

PowerWorld Simulator is easier to trust when the case stays smaller than the grid it came from. A named session shows which power flow case is active, the pins show which buses and branches you will inspect today, and the closing note tells the next person which contingency is next on the oneline diagram. That record is short on purpose: not a copy of every outage, only the path back to the board that is still open.

The same loop fits a student case, a client study, or a computer shared by two operators. Open the last PowerWorld Simulator session, inspect one outage, and leave the contingency list easier to follow than you found it. Wall maps stay where they are. PowerWorld Simulator only holds the power flow case, the summary, and the handoff.

## One Real Pass

Pick a case that already has a name: a small area, a tie line, or a short list of outages. Open it in PowerWorld Simulator, keep only those buses and branches on the board, and read one contingency you can point to. A pass is done when that outage is marked on the oneline diagram and the extra areas are no longer in the way. PowerWorld Simulator does not need a full interconnection model before it is useful.

If the pass feels crowded, the case is too wide. Drop anything that belongs to a different area and leave it out of this workspace. The next pass can have its own title. What matters is that this one stays readable from the first bus to the last branch, with the summary still matching the contingency list on the board.
